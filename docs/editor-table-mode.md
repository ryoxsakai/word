# 表形式での編集

単語・熟語の編集ページ右上の「表形式に切替」で表を開く。「通常編集に切替」で従来の一覧とモーダルへ戻る。選んだ方式はブラウザ内に保存し、単語と熟語で共通に使う。

- 単語帳とSectionを選ぶ。1ページ20件。検索は選択中のSectionの見出しを対象とする。
- 横スクロールで各項目を編集する。左の番号・見出しと列見出しは固定。
- 意味（品詞別発音・代表の意味を含む）、例文／フレーズと訳、派生語はセル内で複数追加・削除・上下移動できる。
- 熟語は別形、複数の意味、Section／Label、同義語・対義語・メモ、非表示を編集できる。既存の単語参照は保持し、表内で確認できる。
- 黄色のセルが変更箇所。「変更を保存」は選択中のSectionの変更行を保存する。各行の「保存」も利用できる。成功時は「保存しました」のトーストを表示する。
- 保存できなかった行には理由を表示し、入力を残す。他の行の保存成功は取り消さない。保存要求は自動再送しない。
- 「戻す」はその行の未保存変更を破棄する。Sectionや編集方式の切替・ページ離脱時は未保存変更を確認する。表の前／次ページでは下書きを保持する。
- 新規の単語・熟語も表から追加できる。単語の番号を空欄にした新規追加は既存APIによる自動採番。

## データ経路

通常の単語帳では一覧・Section詳細・熟語詳細を認証後にR2の既存JSONから読む。詳細用 `editor/sections/:id?full=1` と `editor/idiom-sections/:key` はスナップショットを再利用し、D1へのフォールバックをしない。ローカルで静的配信が無効の場合だけ従来のDB読み出しを使う。

保存直前に変更したレコードを読み直し、変更した欄だけを最新データにマージする。変更欄が既に別の内容へ更新されていれば保存を止める。これは保存直前の比較であり、読み出しから書き込みまでを原子的にロックするものではない。単語本体と所属は既存の別APIなので、所属保存に失敗した場合は本体の保存済み状態を保持し、未保存の所属変更を残す。

親リストには保存済みJSONがないため、軽量索引と表示する20件分の詳細を読み出す。詳細取得は同時3件に制限する。

辞書下書き、音声生成、イラスト管理、Section自体の作成・名前変更などは従来の画面を利用する。表では単語・熟語の編集フォームにある保存項目を扱う。

## 検証

`npm run test:editor-table` は実際のHTMLとJSをDOM環境で動かし、複数項目・変更行保存・非表示データの保持・競合・失敗時の入力保持・トーストを検証する。`test:editor-cache` に含む。`test:snapshots` はD1へのアクセスで例外を投げる環境でも表用の詳細JSONを読めることを検証する。
