# カード形式での編集

単語・熟語の編集ページ右上の「カード編集に切替」でカード一覧を開く。「通常編集に切替」で従来の一覧とモーダルへ戻る。選んだ方式はブラウザ内に保存し、単語と熟語で共通に使う。

- スマホでは1枚を画面幅に合わせ、左右スワイプまたは前後ボタンで移動する。カード内は縦スクロールでき、保存ボタンは上部に残る。
- 単語帳とSectionを選ぶ。一度に20件。検索は選択中のSectionの見出しを対象とする。
- 元のモーダルに沿ったカードを横に並べる。カード内は個別に縦スクロールし、見出し・保存ボタンは上部に固定する。横スクロールまたは「前のカード／次のカード」で移動し、20件の端では次の20件へ進む。
- 意味（代表の意味を含む）、例文／フレーズと訳、派生語はカード内で複数追加・削除・上下移動できる。
- 熟語は別形、複数の意味、同義語・対義語・メモ、非表示を編集できる。既存の単語参照は保持し、カード内で確認できる。
- 黄色の欄が変更箇所。「変更を保存」は選択中のSectionの変更したカードを保存する。各カードの「保存」も利用できる。成功時は「保存しました」のトーストを表示する。
- 保存できなかったカードには理由を表示し、入力を残す。他のカードの保存成功は取り消さない。保存要求は自動再送しない。
- 「戻す」はそのカードの未保存変更を破棄する。Sectionや編集方式の切替・ページ離脱時は未保存変更を確認する。カード移動では下書きと各カードの縦位置を保持し、保存後も横・縦のスクロール位置を維持する。
- 新規の単語・熟語もカードから追加できる。単語の新規追加は既存APIによる自動採番。

## データ経路

通常の単語帳では一覧・Section詳細・熟語詳細を認証後にR2の既存JSONから読む。詳細用 `editor/sections/:id?full=1` と `editor/idiom-sections/:key` はスナップショットを再利用し、D1へのフォールバックをしない。ローカルで静的配信が無効の場合だけ従来のDB読み出しを使う。

保存直前に変更したレコードを読み直し、変更した欄だけを最新データにマージする。変更欄が既に別の内容へ更新されていれば保存を止める。これは保存直前の比較であり、読み出しから書き込みまでを原子的にロックするものではない。単語本体と所属は既存の別APIなので、所属保存に失敗した場合は本体の保存済み状態を保持し、未保存の所属変更を残す。

親リストには保存済みJSONがないため、軽量索引と表示する20件分の詳細を読み出す。詳細取得は同時3件に制限する。

辞書下書き、音声生成、イラスト管理、Section自体の作成・名前変更などは従来の画面を利用する。カードでは単語・熟語の編集フォームにある保存項目を扱う。

## 検証

`npm run test:editor-table` は実際のHTMLとJSをDOM環境で動かし、複数項目・変更したカード保存・非表示データの保持・競合・失敗時の入力保持・トーストを検証する。`test:editor-cache` に含む。`test:snapshots` はD1へのアクセスで例外を投げる環境でも編集用の詳細JSONを読めることを検証する。

互換性のため、保存済みの編集方式キーとモジュール名は従来の `table` を維持する。以前の表形式を選んでいた場合は、そのままカード編集で開く。

## コンパクト表示

注意事項は既存モーダルと同じ短いトグルボタンで選ぶ。品詞と意味は20:80で横に並べ、見出しチェックは上下ボタンの右へ配置する。意味ごとの外枠と品詞別発音欄は表示しない。文章欄は1行から内容・折り返しに応じて自動で高さを調整する。

種類の選択とレベル・タグはカードでは表示しない。追加する例文・フレーズはフレーズとして作成し、既存の種類・品詞別発音・タグは編集と保存を通じて保持する。

カード内のSection・Label・派生元・No.も非表示とし、既存値を保持する。上部のSection選択は引き続き表示する。新規項目は現在選択中のSectionへ追加する。

入力欄・プルダウンの文字は16pxから14pxへ縮小する。
